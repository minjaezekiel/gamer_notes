Screen Coordinates: Y Points Down

The single most common “why is it going the wrong way?” bug. Used in: web L2 · python L2 · c++ L3

In maths class, the y axis points up and zero is in the middle. On a computer screen, the y axis points down and zero is in the top-left corner. Nobody tells you this, and then your first jump sends the player into the floor.

What to look for Drag the orange dot. Watch both readouts at once. Move it upwards and notice that the screen’s y gets smaller while the maths y gets bigger. Then press Play: the ball is told y = y - 90 * dt, and it rises.

So how do you move things?

You want…You write…Because…
move rightx = x + speedx grows to the right, as you would expect
move leftx = x - speedsame as maths class
move upy = y - speedy grows downwards, so up is minus
move downy = y + speeddown is the direction y grows
jumpvy = -400a big negative y speed launches the player upward
gravityvy = vy + 900 * dtgravity pulls down, so it adds to vy
Why is it like this?

It is a leftover from how old screens were built. A cathode-ray television drew the picture with a beam that swept across the top row first, then the next row down, and so on to the bottom. So “row 0” meant the first row drawn, which is the top one. Every graphics system since has kept that numbering, and almost all of them still do: the web canvas, Python’s tkinter, SDL, raylib, and your phone.

One famous exception is Python’s turtle, which deliberately uses maths-class coordinates with y pointing up, because it was built for teaching. You will meet both in this course, which is good: it forces you to always ask which convention you are in.

Find the bug

A student writes a jump and reports that the player “falls through the floor instantly”:

if (keyPressed === "space") {
  player.vy = 400;          // jump!
}
player.vy = player.vy + 900 * dt;   // gravity
player.y  = player.y + player.vy * dt;

What one character needs to change, and why does the player end up going down faster than if they had not jumped at all?

Think like an engineer

Suppose you are building a game where the maths really is easier with y pointing up — say a physics sandbox, or a graph-plotting game. You have two options:

  1. Store everything in screen coordinates and remember to flip signs everywhere.
  2. Store everything in maths coordinates and flip once, in the drawing code.

Which would you choose, and what exactly would the second one cost you? This is a real design decision that engine authors argue about. Write down the one function you would need for option 2.

Vocabulary
  • Origin — the point where x and y are both zero. On a screen it is the top-left corner.
  • Coordinate system — an agreement about where zero is and which way the numbers grow.
  • Pixel — one dot of the screen. Screen coordinates are counted in pixels.
  • Velocity (vy) — speed with a direction. Negative vy means moving up.
