Delta Time

Why your game runs at double speed on your friend’s laptop. Used in: web L2 · python L3 · c++ L3

Not every computer runs your game at the same speed. If you move things “a bit each frame”, then a faster computer gives the player a faster game — which is a bug, not a feature.

What to look for Both balls are told to cross the track at the same speed. Press Play with the frame rate at 60 and they tie. Now drag the frame-rate slider to 20 and press Reset, then Play. The top ball crawls. Nobody changed its speed setting. The bottom ball does not care, because it asks how much time passed rather than counting frames.

The two lines of code that differ

Counting frames — breaks

// "move 5 pixels every frame"
ball.x = ball.x + 5;

Reads as 5 pixels per frame. At 60 fps that is 300 pixels a second. At 20 fps it is 100. The speed of the game is now decided by the computer, not by you.

Using time — works

// "move 300 pixels every second"
ball.x = ball.x + 300 * dt;

Reads as 300 pixels per second. dt is how many seconds the last frame took. A slow computer gets a bigger dt and so takes bigger steps. Same result.

The maths you just used

This is the distance formula from science class, and nothing more:

distance = speed × time

A frame is a very short amount of time. If the last frame took dt seconds and you are going speed pixels per second, you should move speed × dt pixels. At 60 fps, dt is about 0.0167 seconds, so 300 × 0.0167 ≈ 5 pixels. That is where the 5 came from in the first place — but it only works on a 60 fps machine.

Where delta time is NOT enough

Delta time is the right fix for a beginner game, and you should use it everywhere. But it is not perfect. If one frame takes a very long time — say the laptop sleeps, or a tab is in the background — then dt becomes huge and a fast object can jump straight through a wall without ever overlapping it. That is called tunnelling, and the real fix is the fixed timestep, which is the first lesson of the advanced level.

Think like an engineer

Delta time makes movement fair on any machine. Now think about what else in a game is measured in frames by accident:

  • An enemy that fires “every 30 frames”.
  • An explosion animation that advances one picture per frame.
  • A countdown timer that does seconds = seconds - 1 each frame.

Pick one and write down what the player would notice on a very fast computer. Then write the fixed version. Is there any case where counting frames really is the correct choice?

Vocabulary
  • Delta time (dt) — how many seconds the previous frame took. “Delta” is the mathematician’s word for “the change in”.
  • Frame rate — frames per second, fps.
  • Frame-rate dependent — a bug where the game behaves differently depending on how fast the computer is.
  • Tunnelling — passing straight through a wall because one step was too big.
