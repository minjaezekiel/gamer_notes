Gravity, Velocity, Position

Three numbers in a chain. Used in: web L2 and L6 · python L5 · c++ L5

Gravity in a game is not complicated physics. It is one line of code that adds a small number to another small number, 60 times a second. The clever part is that there are two levels of adding, not one.

What to look for Press Step 1 frame slowly and read the table. Each frame, gravity is added to the velocity, and then the velocity is added to the position. Watch the velocity number grow steadily while the gaps between the ball’s positions grow faster and faster. That is why falling feels like falling.

The chain, in three lines

// Gravity is an ACCELERATION: a change in speed, not a speed.
// It never changes. It is a constant of your game world.
const GRAVITY = 900;          // pixels per second, per second

// 1. Gravity changes the VELOCITY.
ball.vy = ball.vy + GRAVITY * dt;

// 2. The velocity changes the POSITION.
ball.y = ball.y + ball.vy * dt;

// 3. Hit the ground? Turn the velocity around, and lose a little energy.
if (ball.y > groundY) {
  ball.y = groundY;              // do not let it sink below the floor
  ball.vy = ball.vy * -0.7;      // -1 would bounce forever; 0.7 keeps 70%
}
The physics you just used

Three words that get mixed up constantly:

  • Position — where it is. Measured in pixels.
  • Velocity — how fast, and which way. Measured in pixels per second. Negative means upward.
  • Acceleration — how fast the velocity is changing. Measured in pixels per second, per second.

Each one is the rate of change of the one above. That is the entire idea, and it is also the central idea of calculus — which you will meet in a few years, and will already understand, because you will have built it.

Why “per second per second”? Because gravity does not say how fast you are going. It says your speed increases by 900 pixels per second, every second. After one second you are falling at 900. After two, at 1800.

Why a jump is the same code

There is no special jump code. A jump is just setting the velocity to a big negative number once, and then letting the same two lines run:

if (jumpKeyPressed && ball.onGround) {
  ball.vy = -500;        // one single push upward
}
// gravity then does the rest, every frame, with no extra code

Gravity immediately starts adding to that -500, so it becomes -480, then -460, until it passes through zero at the top of the arc and turns positive. The ball slows down, stops, and falls — and you never wrote any of that. You got a realistic arc for free. This is what people mean when they say a simulation “emerges” from simple rules.

Think like an engineer

Real gravity on Earth is about 9.8 metres per second per second. Our game uses 900 pixels per second per second. These are not the same number and that is fine — but it raises a question:

Most platform games use gravity far stronger than real life, and make the player fall faster than they rise. That is physically wrong, and it feels better. Why do you think that is? Pick a platform game you know and try to describe its gravity in words. Then change GRAVITY and the bounce factor in the demo above and find a combination that feels good rather than correct.

Vocabulary
  • Acceleration — the rate at which velocity changes.
  • Constant — a number that never changes while the game runs. Written in CAPITALS by convention, so a reader knows not to look for where it is modified.
  • Restitution — the fancy name for the bounciness number. 1 means a perfect bounce, 0 means it sticks.
  • Terminal velocity — a speed cap, so a long fall does not become impossible to control or tunnel through the floor.
