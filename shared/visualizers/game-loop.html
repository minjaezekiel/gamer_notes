The Game Loop

Every game ever made is this one shape. Used in: web L1 · python L1 · c++ L1

A game is not a program that runs once and stops. It is a program that does the same three jobs over and over, forever, until you quit.

What to look for Press Step 1 frame three times. Each press does one job, not one whole frame. Watch which box lights up, and notice that the square only moves during UPDATE and only appears somewhere new during RENDER. Then press Play and watch the same three jobs cycle so fast it looks like smooth movement.

What you just watched

The three jobs always happen in this order, and the order matters:

JobWhat it doesIf you skipped it
INPUT Look at the keyboard, mouse or controller. Write down what the player is asking for. The game ignores the player completely.
UPDATE Change the numbers. Move things, check for collisions, add to the score. Nothing ever changes. A frozen picture.
RENDER Erase the screen and draw everything where it is now. Things move, but you never see it. The screen stays on frame 1.
The mistake almost everyone makes first

Beginners often try to move something and draw it in the same step, over and over, inside one frame. That draws the ball in ten places at once. Update everything first. Then draw everything. Keep the two jobs apart and most mysterious glitches never happen.

The same loop in all three languages

Look at the shape, not the words. It is identical.

function frame() {
  readInput();
  update();
  render();
  // ask the browser
  // for the next frame
  requestAnimationFrame(frame);
}
frame();
while running:
    read_input()
    update()
    render()
    # wait a moment so the
    # loop is not too fast
    time.sleep(1 / 60)
while (running) {
    read_input();
    update();
    render();
    // wait a moment so the
    // loop is not too fast
    sleep_for(16ms);
}
Think like an engineer

A game runs its loop about 60 times a second. A chess program does not: it waits, possibly for minutes, until you move a piece. Both are games.

So what decides whether a program needs a continuous loop or can just wait for input? Write down three games of each kind, then try to state the rule in one sentence.

Vocabulary
  • Frame — one trip around the loop. One picture, like one page of a flipbook.
  • Frame rate — how many frames happen per second. Written fps.
  • Game loop — the input / update / render cycle that repeats forever.
  • State — all the numbers the game is currently remembering.
